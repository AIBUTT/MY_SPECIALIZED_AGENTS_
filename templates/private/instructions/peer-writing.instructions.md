# Peer-facing writing standard

These files are read by engineers and scientists reviewing the work. Write as a technical report, not as a conversation.

## Register

- Use an impersonal or first-person-plural academic voice ("the analysis shows", "we tested"). Never use first-person singular.
- No conversational or promotional language: avoid "pivot", "dud", "honest", "the fix", "what ships", "proves", rhetorical questions as headings, and exclamations.
- Headings describe content (for example "Alternative explanations tested", "Limitations"), not narrative drama.
- Frame each design change as **initial design, evidence, revision**. State reversed recommendations neutrally ("was initially proposed; the data did not support it").
- Never mention AI, agents, Copilot, prompts, handoff files, or `.github/`. Never imply that results were generated by an assistant.

## Precision of claims

- Use calibrated verbs: "indicates", "is consistent with", "suggests", "estimated". Reserve "shows" for direct measurements; avoid "proves" unless a formal proof exists.
- Label model-based estimates as estimates and name their model.
- Flags are statistical alerts, not confirmed findings. Population-level excess is an estimate, not a count of confirmed cases.
- Label historical and superseded results as such.
- Keep every limitation, open question, and unresolved decision visible.
- Report metrics with their uncertainty (interval, spread across folds or repeats) and the baseline they are compared with.

## Figures and tables

- Every figure has labelled axes with units, a caption that states what is plotted and from which run, and a colour-blind-safe palette.
- Every table states its unit, denominator, and source artifact.

## Number preservation

Language edits must not change any result. Do not round, recompute, or "correct" a number unless a cited artifact supports it, and then list it explicitly. After editing a file that is already staged in Git, compare its numeric tokens with the staged version:

```powershell
conda run -n {{conda_env}} python -c "import re,subprocess,sys,collections as c;p=sys.argv[1];old=subprocess.run(['git','show',':'+p],capture_output=True,encoding='utf-8').stdout;new=open(p,encoding='utf-8').read();f=lambda t:c.Counter(re.findall(r'\d[\d,]*(?:\.\d+)?',t));o,n=f(old),f(new);print('removed',dict(o-n));print('added',dict(n-o))" reports/<file>.md
```

Every removed or added token must be explained in the handoff (section references, deleted sentences, values quoted from an existing table). Any unexplained change blocks acceptance.
